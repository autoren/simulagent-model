# V152 fresh question-order-only population plan

## Purpose

V151r1 separated system safety from model quality but combined two model claims in one realization: proposing a compatible state set and ordering registered clarification questions. The state-proposal claim failed and is unnecessary to the trusted controller. V152 therefore creates a fresh controlled population in which no model-facing or controller-facing field can propose, rank, or prune semantic states. A later model may affect only question order.

The architecture is fixed as:

```text
request
  -> complete authoritative state universe remains retained
  -> a heuristic orders six registered closed questions
  -> irrelevant questions return no trusted selection and remain A00
  -> the discriminating question produces a closed typed answer
  -> the immutable witness firewall determines the final state
```

## Population

The population contains four declared known capabilities, a generic non-executable novel-candidate state, an unsupported state, and operational insufficient evidence. Six families contrast known dental, coffee-delivery, art-shipment, and bicycle-protection mechanics with nearby unregistered or forbidden mechanics. All identifiers, domains, utterances, slots, and question text are fresh relative to V135, V142, V146, and V149.

Each of 48 groups contains familiar known language, unfamiliar known language, clear right-hand language, an ambiguous request, a closed answer selecting the known interpretation, and a closed answer selecting the right-hand interpretation. Four groups per family form development and four form a sealed project-authored evaluation partition, producing 288 fixtures. The later question-order study will use the 96 development request fixtures only; evaluation language remains sealed until separately authorized.

## Trust boundary

Six registered two-option questions map exact answer events to typed witnesses. Before a valid answer, the final state is `A00`, even for apparently clear language. A malformed, irrelevant, absent, or contradictory answer produces no trusted witness and fails closed. The finalizer always retains all seven authoritative hypotheses and cannot register or execute a capability.

Public and hidden fixtures contain no `presented_candidate_choice_id`, candidate state list, model state ranking, or other semantic proposal field. The later model prompt may see the declared catalog and registered questions only to order questions; its output can never narrow the state universe or satisfy a witness.

## Gates and authorization

The design audit requires exact group and split counts, public/hidden alignment without truth leakage, zero candidate-proposal fields, exact answer-to-witness routing, fail-closed pre-answer and malformed events, exact conversation non-overlap with prior controlled populations, complete hypothesis retention, and zero model, API, training, or execution access.

Passing authorizes only a model-free comparator study that freezes source order, seeded random order, and oracle order with explicit costs. It does not authorize a model run, evaluation access, reasoning-condition comparison, calibration, threshold fitting, induction, authority, action, or execution.
