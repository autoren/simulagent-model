# V165 factored ontology-identifiability population plan

## Question

Can the next ontology branch represent two questions separately before asking a language model to answer either?

1. Is a target concept extensionally expressible by the frozen registered DSL as an alias or bounded
   composition, or does it require a provisional primitive relative to that DSL?
2. Does the supplied evidence identify one candidate, leave several candidates possible, or contradict itself?

V164 showed why the separation matters. A model could ground known and unsupported requests while making zero
NOVEL predictions. One status field forced catalog membership and evidence sufficiency into the same choice.

## Finite proof domain

V165 uses three typed Boolean unary predicates over `Device`. The exhaustive intervention domain contains all
eight valuations. The registered DSL contains exactly three atoms and the AND/OR of each distinct atom pair,
for nine distinct registered truth tables. All 256 Boolean truth tables are enumerated as shadow candidates;
the remaining 247 are called provisional only because they are not expressible in this bounded DSL.

This gives “provisional primitive” a precise relative meaning. V165 makes no claim of absolute novelty.

## Factorial population

The population crosses three generative expressibility classes with three evidence statuses. Each of the nine
cells contains four logical target groups under four independent primitive/entity renamings: 16 records per cell,
144 records total. There is no evaluation split.

- Sufficient alias/composition cases have an exact controlled definition and consistent positive/negative
  interventions.
- Sufficient provisional cases expose the complete eight-valuation intervention table for one non-DSL function.
- Ambiguous cases use an underspecified definition and a minimal observation subset that retains the target plus
  candidates from alias, composition, and provisional classes.
- Contradictory cases repeat one identical intervention with opposing labels, so no deterministic truth table is
  consistent.

An exact parser and exhaustive version-space calculation must automatically prove the registered contract for
every record. Noncontradictory evidence must retain the generative target. Sufficient cases must have exactly one
candidate, ambiguous cases multiple candidates spanning all three classes, and contradictory cases none.
Renaming must leave version-space sizes and expressibility-class sets invariant.

## Boundaries

This is project-authored synthetic development evidence. It is not human-authored, externally confirmed, or a
language-model result. Public records exclude target functions, factors, version spaces, and identifiability
labels. The authoritative ontology remains immutable; all candidates are shadow-only. Evaluation data, models,
APIs, training, ontology registration, services, side effects, action, and execution remain zero.

Passing authorizes only a separate prospective V166 design for deterministic parsing, ontology retrieval, exact
enumeration, version-space retention, and oracle controls. It does not authorize immediate scoring or any model.
