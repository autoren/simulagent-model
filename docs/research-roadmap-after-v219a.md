# Research roadmap after V219A

## Frozen conclusion

V219A positively identifies one fully untouched adjacent Mondo release pair for a fresh payload study:
`v2026-05-05 -> v2026-06-02`. Both eligible pairs passed all metadata gates; the selected pair follows the frozen
newest-first rule. The selected eight-asset contract totals 96,095,320 bytes and is attested by published SHA-256
digests. The content-hashed official June API release body—not a README—supplies the four-category release control.

This is metadata feasibility only. No selected asset was downloaded or parsed in V219A.

## V220: fresh untouched-pair payload and population study

The next goal should preregister and prospectively audit exactly one retrieval/population protocol before reading a
payload byte. It should:

1. inherit the selected pair, eight exact URLs, byte counts, and published digests from the V219A outcome lock;
2. retrieve each asset exactly once, reject any byte-count or digest mismatch, preserve raw files, forbid remote import
   resolution, and make no unlisted request;
3. use the already-frozen V217A API body and its V219A hash as the release-summary control without another API call;
4. retain V218's useful asserted-state parser, stable-ID/replacement/consider family construction, paired
   version-unspecified/current-release evidence, boundary witnesses, decision consequences, identifier redaction, and
   group-disjoint development/protected split;
5. preregister event-stratified direct gates so the expected addition stratum cannot compensate for absent text,
   lifecycle, mapping, or ambiguity evidence;
6. use pair-specific new/changed TSV controls and both releases' candidate-status/source-version controls;
7. keep every V218-derived record excluded and sealed rather than treating the new run as a repair; and
8. freeze a negative result without parser, source-role, population, split, or gate tuning if any control fails.

Protected records may be created and structurally hashed, but they remain sealed against semantic or method
evaluation. V216, V213, and V218 protected material remains closed.

## Conditional deterministic track

Only a verified-positive V220 may authorize a new development-only deterministic control study. That study should
measure exact parsing, candidate retrieval, normalization, bounded synthesis where applicable, version-space collapse,
contradiction handling, and the residual oracle classes left unresolved. Protected evaluation remains a later,
separately locked confirmation.

Only if a meaningful development residual survives may one bounded local LLM be considered as a candidate generator.
Its criterion remains incremental oracle-class recall at a fixed candidate budget, not top-1 accuracy. The deterministic
validator, version space, abstention path, and certificate-aware planner remain authoritative. An API is not required.

## Parallel external-semantics track

Historical ontology artifacts can validate retrospective reconstruction and decision consequences. They do not reveal
what a new speaker intended. Strong B2c claims remain a parallel deferred track requiring appropriate speaker/domain
evidence or a resource whose provenance directly supplies that semantic judgment. Simulated people cannot upgrade the
retrospective track into that claim.

## Preserved boundaries

- No in-place V218 repair or reuse of its development/protected population.
- No thresholds selected from V218 or V219A payload contents.
- No new payload access before the V220 design lock.
- No protected method evaluation, local/API model, training, ontology registration, trusted-state mutation, service
  action, or execution.
- All results concern retrospective versioned artifacts until independent evidence supports a new-speaker claim.
