# Research roadmap after V213

## Frozen transition

V213 passed and outcome-froze a fresh role-separated population with 120 opaque groups, 480 typed program records, a
balanced group-disjoint 320/160 development/protected split, zero public truth leakage, and exact V212 oracle
reconstruction. The protected partition has not been used for downstream method development or evaluation.

The primary sequence now moves to V214 deterministic candidate and version-space controls.

## V214 development scope

V214 should be prospectively frozen against the V213 development partition only. It should compare a bounded ladder:

1. exact structural parser and evaluator;
2. normalized exact retrieval with group/self matches excluded;
3. typed approximate retrieval;
4. bounded syntax enumeration and synthesis;
5. reference and observation constraint propagation;
6. behavioral-equivalence collapse;
7. contradiction and outside-interface handling;
8. boundary-query selection for residual version spaces.

Every control must emit candidate behavioral class IDs, not only a top label. Scoring should measure oracle-class
recall at fixed candidate budgets, exact version-space recovery, false-class proposal, candidate-set size, evidence and
expressibility status, safe deferral, group/variant invariance, and downstream shadow-decision regret.

The exact structural parser is an oracle-aligned ceiling, not a realistic language baseline. Retrieval and bounded
synthesis are the meaningful deterministic controls. V214 should report which mechanism closes each family and leave a
precise residual taxonomy.

## Protected boundary

V214 method construction and selection use only the V213 development group IDs. The protected public records and
sealed truth remain unopened. A later confirmation stage requires a separate prospective lock after V214 chooses one
unchanged deterministic stack and freezes every budget, normalization, tie-break, and abstention rule.

## Conditional model branch

A bounded local LLM is eligible only if the best frozen deterministic stack leaves a nonzero residual satisfying all of
the following:

- the missing oracle classes are expressible from the public evidence;
- residual errors are not merely outside, intentionally ambiguous, or contradictory records correctly deferred;
- incremental candidate generation could change a shadow decision;
- the residual is large enough for a prospectively powered comparison;
- a fixed candidate budget and low/medium reasoning budget can be frozen without treating truncation as abstention.

If those conditions fail, the correct branch is deterministic closure with zero model eligibility.

## Parallel and downstream tracks

The metadata-first external-resource feasibility track remains separate and requires its own lock before accessing
ontology payloads. Any provisional candidates surviving a later model branch should reuse the existing reversible
sandbox and certificate-aware planner; no new execution authority is needed.
