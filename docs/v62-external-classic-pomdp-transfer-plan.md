# V62 external classic-POMDP belief and planning transfer

V61 completed the report's internal sequence through bounded verified planning. V62 is an external-validity probe rather than another internal DSL extension. It asks whether exact history-dependent Bayesian filtering and finite-horizon decision-making reproduce independent references on three models taken unchanged from POBAX at a pinned upstream commit.

The benchmark has six prospectively fixed cells: Tiger at horizons 1, 3, 5, and 7; T-Maze length 2 at horizon 4; and T-Maze length 5 at horizon 7. Tiger supplies noisy sensing and a genuine listen-before-commit decision. The two T-Mazes require retaining an early goal observation until a later junction. Exact history-dependent planning is compared with observation-only, MAP-collapse, uniform-random, and fully observed controls. These controls localize failure modes; they are not trained-agent leaderboards.

The candidate uses a new strict parser for the selected Cassandra `.POMDP` syntax, an exact normalized belief update, and memoized finite-horizon Bellman recursion. It may not import POBAX's parser/runtime or any V49--V61 filtering or planning implementation. A separate scalar parser, separate public-history recursion, one-step Bellman recomposition, six analytic fixtures, and twelve implementation mutants audit it before any external bundle exists.

After the implementation is frozen, a detached checkout at commit `a5e1d62d14e4efe783885b9d4f19cffa2a568eec` contributes only the declared model files, parser/runtime source, and Apache-2.0 license to an ignored hash-sealed bundle. Candidate evaluation is offline. A separate Python 3.12/JAX process loads the unchanged POBAX runtime by file path and executes 4,096 episodes for each task-policy cell. Empirical discounted returns must agree with exact values under a familywise 99% Hoeffding bound.

All 32 gates are noncompensatory. They cover source/license binding, independent parsing, probability normalization, exact value/action agreement, reachable-belief normalization, Bellman residuals, terminal semantics, external-runtime completion and Monte Carlo agreement, the prospectively expected Tiger and T-Maze control separations, mutation/fixture controls, hashes, versions, attempt count, and zero human/model access.

A pass establishes only exact finite-state, finite-horizon belief/planning transfer on these three pinned external models. It does not establish portability of the project's SMC2 mechanic estimator, unknown-program inference outside the DSL, generic POMDP scalability, continuous or long-horizon control, formal safety, human-authored language robustness, or model/adapter performance.
