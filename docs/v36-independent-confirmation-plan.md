# V36 design preregistration: independent modular-interface confirmation

## Claim and purpose

V34 and V35 are strong but exposed-development results. V36 will ask whether the fully fixed
modular language interface transfers once to genuinely new surface families under the same
declared typed ontology and supported five-operation inventory. It is an independent development
confirmation, not a final scientific result.

The immediate design stage freezes the population, interface, metrics, gates, and decision rules.
It authorizes implementation only. It does not yet authorize fitting the interface, constructing
the confirmation corpus, opening confirmation labels, reusing V32 evaluation, running V28, or
constructing a final suite.

## Frozen interface

The confirmation system is fixed exactly from the audited V34/V35 selections:

- predicate: V35 atom-focused final hidden state, balanced ridge, alpha 10,000;
- entity binding: V35 evidence-only entity mentions, fixed seed-3501 Gaussian projection to 256
  dimensions, balanced three-role ridge, alpha 1,000;
- lexical sign: V32 generic final hidden state, balanced ridge, alpha 100;
- outer operation: V34 operation-focused final hidden state, balanced ridge, alpha 10,000; and
- truth status: the unchanged deterministic V32 sign-by-operation compiler.

All four readouts will be fit once on V32 `factor_fit` only and hash-frozen before confirmation
construction. No checkpoint, prompt, method, alpha, projection, threshold, label map, or compiler
may be selected after this design lock.

## Independent confirmation population

The suite contains 15 new surface families: three newly authored realizations for each of assert,
deny, double denial, contrast selection, and unresolved evidence. Every family contains both
positive and negative embedded literals, including the negative denial/double-denial/contrast
cells absent from V32 fit. It preserves direct, inverse, distractor, and argument-reversal controls
with 3, 4, and 5 entities.

The frozen construction quota is 1,170 clauses in 360 scenes. No evidence string or normalized
surface construction may overlap any V32 split. The ontology and operator inventory remain fixed;
this is not an ontology-learning or open-language test.

## One-shot execution

After the interface parameters are frozen and the constructed suite passes structural/firewall
audits, each clause receives exactly three frozen-model forwards: generic sign, operation-focused,
and atom-focused. Total planned forwards are 3,510. Model prompts contain no targets.

The confirmation is scored once. The statistical unit for uncertainty is the surface family, with
10,000 fixed-seed bootstrap replicates. Report component accuracy, compiled truth, exact fact,
exact scene, worst-family exact fact, negative-composition exact fact, and registered structural
pair accuracy.

## Gates and next decision

Passing requires predicate 0.98, atom 0.95, relation order 0.95, sign 0.95, operation 0.95,
compiled truth 0.95, exact fact 0.90, exact scene 0.80, worst-family exact fact 0.80,
negative-composition exact fact 0.90, and every registered pair category 0.90.

- If every gate passes, preregister a genuinely fresh sealed end-to-end relational suite that
  combines language grounding with probabilistic graph/program inference.
- If a semantic component fails, reopen only sign/operation interface development.
- If an atom component fails, reopen only predicate/binding development.
- If components pass but exact fact or scene fails, investigate assembly dependence.

No V36 outcome retroactively validates V32 evaluation and no failure automatically authorizes
LoRA or a stronger model.
