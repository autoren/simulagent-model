# V65r3 preregistration: synthetic-only implementation EIG firewall

Date frozen: 2026-08-16

V65r3 carries forward the exact-zero identity repair from V65r2 without algorithmic change. V65r2
was rejected before its implementation lock because a development test called the candidate scorer
on one sealed record. V65r3 repairs that access protocol, not the method or evaluation design.

Before an evaluator lock, the sealed fatal record may be used only for Boolean support, SMC²
identity evidence and posterior inference, normalization, exact-zero identity mass and atom
exclusion, and work/random-stream diagnostics. It may not reach a candidate predictive, EIG,
selection, exact-candidate reference, regret, or accuracy-gate function.

Every implementation-stage candidate-scoring test must use a declared synthetic public history. A
firewall must compare both record ID and the complete public history against all 48 sealed records
before allowing a scorer call. The synthetic fixture is fixed as reset `left`, actions `[n, e]`, and
observations `[left, neither]` under record ID `v65r3-synthetic-eig-fixture`.

The algorithmic rules remain unchanged: structurally impossible identities contribute log evidence
`-Infinity`, zero mass, and no atoms; both identities impossible is an invalid history; finite
particle extinction under positive Boolean support is a hard error. Ordinary positive-support paths
must remain bitwise identical to V65r1.

After an implementation lock, a separate evaluator audit must add the atomic attempt marker and
terminal failure serialization. Only then may one V65r3 evaluation score the unchanged 48-record
subset under the original budgets, repeats, exact reference, controls, and noncompensatory gates.
V65r3 cannot authorize reward planning unless that one evaluation passes every gate.
