# V149 fresh closed-interaction population plan

V149 creates the first population under the V148 trust boundary. It contains four declared known capabilities, a generic non-executable novel-candidate state, an unsupported state, and operational insufficient evidence. Six families pair known mechanics with nearby unregistered or forbidden mechanics.

Each of 48 groups contains six stages: familiar known language, unfamiliar known language, clear right-hand language, an ambiguous request, a closed answer selecting the known interpretation, and a closed answer selecting the right-hand interpretation. Four groups per family form development and four form a sealed project-authored evaluation partition, for 288 fixtures total.

Six registered clarification questions each have two option IDs. An answer event contains only a query ID and selected option ID; the immutable query catalog maps that event to a complete typed witness. The optional LLM candidate cannot alter the mapping. Before a valid answer event, the firewall remains `A00`, including on apparently clear utterances. This deliberately measures the cost of trusted evidence rather than treating model confidence as authority.

The design audit requires complete groups and splits, hidden-ground-truth separation, exact answer-to-witness routing, fail-closed malformed events, complete hypothesis retention, and zero exact conversation overlap with V135, V142, and V146. No model, API, training, authority, action, or execution is permitted.

Passing authorizes only a model-free oracle policy study. A later language/model realization would require another prospective lock and would remain synthetic development evidence.
