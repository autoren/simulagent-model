# Research roadmap after V218

## Frozen conclusion

V218 is a verified negative result. Eight of nine scientific/control components behaved as intended; the sole failed
component was the preregistered published-release-summary control. The downloaded `README.md` asset is a repository
README, not the detailed GitHub release body. Its frozen summary-category coverage was `0.25` instead of `1.0`.

The project must not drop that gate, change the README parser, substitute the GitHub API body after exposure, or use
the V218 development/protected population as though V218 passed. V218 does not authorize deterministic controls.

## Strong descriptive boundary result

The failure is narrow and informative. The exact pair otherwise yielded:

- 385 eligible concept families and 770 paired evidence-mode records;
- 49 text-change and seven lifecycle-event families;
- 381 ambiguous version-unspecified families;
- 385 families with a decision contrast after current-release evidence;
- exact state, version-space, witness, and consequence reconstruction; and
- 289 development and 96 sealed protected groups with no overlap or identifier leakage.

This confirms that Mondo is scientifically promising for artifact-grounded representational diagnosis. It does not
convert the negative outcome into a pass.

## Primary next track: untouched-pair release-control census

An in-place V218 repair is inappropriate because the control role would change after payload exposure. The next stage
should instead be a metadata-only, prospectively frozen selection over adjacent Mondo pairs whose ontology bodies were
not opened in V218.

Before computing the selection, that census should freeze:

1. exclusion of `v2026-07-06` and `v2026-08-04`, because both were opened in V218;
2. adjacent-pair candidates derived only from the already-frozen V217A release metadata;
3. deterministic priority, preferably newest fully untouched adjacent pair first;
4. exact main assets, diff controls, two-release candidate-status controls, and source-version controls;
5. per-asset and total byte ceilings;
6. release-summary evidence taken from the content-hashed official GitHub API release object itself, not an asset whose
   semantic role is inferred from its filename;
7. required release-body categories and lifecycle evidence; and
8. a negative stop if no fully untouched pair satisfies every control and budget requirement.

This stage should not make network requests or read any new ontology payload. It should select at most one pair for a
later separately locked payload protocol.

## Conditional fresh payload successor

Only a positive untouched-pair census may authorize a new payload design. The successor should preserve V218's useful
architecture—exact asserted states, lifecycle-linked concept families, paired evidence modes, boundary witnesses,
decision consequences, and group-disjoint protection—while correcting the provenance role prospectively:

- the frozen API release object is the published summary control;
- downloaded TSVs are tabular diff/status/provenance controls;
- no repository README is treated as release-note evidence;
- event-stratified reporting prevents a large addition batch from hiding smaller text and lifecycle strata; and
- direct family/event/ambiguity gates remain, with no total-term threshold.

The V218 pair and all of its derived records are excluded from the fresh study.

## Method and model status

Deterministic method evaluation remains unauthorized because V218 is negative. If a fresh untouched pair later passes,
deterministic parsing, retrieval, normalization, version-space collapse, contradiction handling, and exact residual
analysis still come before any model.

A local or API model remains optional and may only generate candidates on a separately frozen development residual at
a fixed budget. It must add oracle-class recall beyond deterministic controls. It cannot serve as a semantic oracle or
turn retrospective curator evidence into a claim about new-speaker intent.

## Preserved boundaries

- V218's 96 protected groups are sealed and may not be opened or reused.
- V216 and V213 protected data remain sealed.
- No current threshold, parser, payload, source role, split, or gate is tuned after exposure.
- No local/API model, training, ontology registration, trusted-state mutation, service action, or execution is
  authorized.
- Historical Mondo artifacts support retrospective reconstruction only; strong B2c new-speaker claims still require
  appropriate speaker or domain-expert evidence.
