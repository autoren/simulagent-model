# V148 typed semantic-witness firewall plan

V147 showed that a complete fixed menu solves output syntax but not open-world membership: the local model still collapsed nearby novel and ambiguous requests into known capabilities. V148 therefore changes the trust boundary rather than tuning the model.

A known capability may be accepted only when an exact typed witness arrives from a closed, trusted clarification channel. The optional LLM proposal is recorded as non-authoritative and cannot satisfy, alter, or override that witness. A valid but unregistered mechanic routes to the generic, non-executable `N00` novel-candidate state; an exact registered forbidden mechanic routes to `U30`; incomplete, malformed, contradictory, or explicitly insufficient evidence routes to operational `A00`.

The model-free census crosses 14 valid witnesses with all seven possible LLM proposals, tests ten malformed witnesses, and applies twelve one-field near-known mutations while the misleading proposal names the known capability. Gates require exact routing, perfect candidate invariance, perfect known precision and recall under oracle witnesses, complete hypothesis retention, and zero language, model, API, training, authority, or execution access.

Passing proves only structural feasibility under trusted typed evidence. It does not prove that an LLM or free-form utterance can produce a trustworthy witness. It may authorize design of a wholly new blind interaction population with simulated closed-option answers, but not a language/model run or capability induction.
