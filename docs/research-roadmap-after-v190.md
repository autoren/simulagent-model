# Research roadmap after V190

## Established boundary

V186–V190 separate four questions that had previously been conflated:

1. **Finite identifiability:** yes. The 14 frozen SGD capability contracts have unique answer vectors under the
   allowed typed codebook, and all 91 pairs are separable.
2. **Binary-channel economics:** conditional. V188 found entropy `3.6342540514` bits, an unrestricted Huffman
   expected depth of `3.7`, and a restricted exact-tree expected depth of `3.9416666667`. At generic clarification
   cost `0.40`, the exact binary policy has positive value through question cost `0.0875` and switches to generic
   clarification at `0.09`; V187's `0.10` negative is therefore reproduced rather than revised.
3. **Adaptive value in the frozen channel:** no. At every positive V189 multiway condition, the exact policy equals
   the best fixed open loop. The useful structure is a fixed hierarchy, not history-dependent question selection.
4. **Finite typed menu compression:** yes, narrowly. V190 independently confirmed on sealed protected identity
   bindings that the prospectively fixed `domain -> normalized intent concept` policy costs `0.38`, versus `0.40`
   for generic clarification, with exact target retention and typed completion `1.0`.

V189 remains a formal failed run because its preregistered scientific gate incorrectly required the pure-bit result
not to beat generic clarification while its decision rule defined robust value as beating generic clarification.
That contradictory gate is not repaired or reinterpreted. V190 is a separate fresh confirmation of the unexpected
development pattern, not a V189 repair.

## Claim boundary

V190 supports only a finite-oracle menu-compression claim. It does not establish:

- adaptive planning advantage;
- open-world language understanding;
- whether an utterance reveals the correct domain or intent menu;
- human answer accuracy, response time, or cognitive burden;
- local- or API-model reliability;
- robustness to malformed, truncated, ambiguous, or adversarial language;
- ontology extension, capability registration, trusted mutation, action, or execution.

Dataset annotations instantiate simulated typed answers. Protected utterance language was never read.

## Active next track: non-authoritative language-to-menu evidence

The next missing premise is whether independently authored language can reduce the confirmed hierarchy without
silently deleting the true contract. This must be studied on a new unprotected development population rather than
the V185 residual or any protected utterance.

### Stage 1: population and interface feasibility

1. Freeze a fresh record-disjoint population with hidden full-contract targets and visible utterance payloads.
2. Keep target annotations outside every proposal input and audit exact identifier, payload, and role separation.
3. Define a shadow-only proposal interface whose outputs can rank domain and intent menus or recommend generic
   clarification, but cannot accept, reject, register, or prune an authoritative hypothesis.
4. Map missing, malformed, truncated, unknown, and out-of-catalog output deterministically to `INSUFFICIENT`.
5. Compute the oracle proposal-quality and retention frontier needed to improve on fixed cost `0.38`; stop if the
   required accuracy or coverage is structurally implausible.

### Stage 2: model-free controls

Compare the unchanged fixed hierarchy with complete-catalog deterministic retrieval, always-generic clarification,
and a target-informed oracle. Score target retention, menu size, false exclusion, expected clarification cost,
selective risk, and performance by known/provisional/unsupported/missing class. The full 14-contract set remains the
authoritative fallback after every proposal.

### Stage 3: one bounded local-model condition, only if authorized

If the population, interface, and model-free controls pass, preregister one local model as a shadow menu ranker. Use
low reasoning effort, a bounded output budget, deterministic parsing, no retry-based selection, and a complete audit
of truncation. Compare it against the frozen deterministic controls and the target-informed oracle. An API is not
required and should be a separately justified later condition, not a prerequisite or silent fallback.

### Stage 4: fresh confirmation, only after a development pass

Freeze the complete proposal-plus-controller policy before opening a separately sealed confirmation role. A pass may
support only non-authoritative menu reduction. It still cannot authorize ontology induction, trusted mutation, action,
or execution.

## Parallel tracks

- **Track A — external language transfer:** the active sequence above.
- **Track B — reversible trusted sandbox:** complete for the current bounded fixed ontology; reopen only for a newly
  validated typed interface, never directly from model output.
- **Track C — shadow ontology acquisition:** deferred until Track A can retain the correct finite contract reliably;
  any provisional concept remains non-authoritative and sandbox-only.
- **Track D — clarification reliability and human factors:** deferred because no independent human participants are
  available. Synthetic or model answers must be labeled as simulations and cannot substitute for human evidence.
- **Track E — richer decision problems:** later. Couple semantic uncertainty to delayed control only after the
  observation interface is reliable enough to make the decision problem identifiable.

## Stop rules

Stop the language-to-menu branch if its oracle frontier cannot improve on `0.38`, deterministic controls exclude the
true target too often, model output adds no value beyond retrieval, or safe fallback erases the cost advantage. Do not
repair failure by reading protected language, weakening complete-target-retention, treating confidence as authority,
changing the V190 cost model retrospectively, adding an API model, or allowing execution.
