# V21 decision and V22 research direction

## Decision from the sealed result

V21 accepts the narrow population-transfer claim under its declared scope. The unchanged hard
pipeline completed 40/40 mechanics with mechanic-macro exact match 1.000, target retention 1.000,
and no empty version spaces. All four construction families were perfect. The calibrated
probabilistic challenger was also exact and introduced no excess outcomes under supported
language. The independent zero-forward-pass replay reproduced every condition and gate.

This does not establish arbitrary world-model learning. The suite used a declared four-variable
Boolean ontology, generated language, a bounded DSL, deterministic one-step outcomes, and a
declared stratified mechanic mixture. Its exact 95% complete-mechanic interval of [0.912, 1.000]
describes that mixture, not an unrestricted population of environments.

The paired novel-ontology result remains a boundary: hard mechanic macro was 0.873 with 25/40
complete mechanics, and the probabilistic interface was 0.873 with the same 25/40. The challenger
therefore preserved the successful supported interface but did not repair ontology transfer.
Further threshold tuning or LoRA is not justified by V21.

## V22 question

Can an uncertainty-aware executable system transfer across variable entity bindings, relation
graphs, and entity counts when language support remains in-distribution and dynamics remain
deterministic and one-step?

V22 should isolate relational state before adding sequential belief dynamics. Introducing open
ontologies, stochastic effects, long horizons, and active intervention at the same time would make
a failure uninterpretable.

## V22 development benchmark

The first benchmark should be openly developed rather than immediately sealed. It should contain:

- two to four typed entities per episode;
- Boolean unary attributes and directed binary relations;
- deterministic one-step visible outcomes;
- a finite typed relational DSL with explicit variable binding;
- support traces that identify the target program under oracle grounding;
- queries that separate familiar bindings, novel graph topology, and entity-count extrapolation;
- supported V14 language operators as the primary condition; and
- paired novel entity and relation labels as a non-gating diagnostic.

Generator families should vary the source of relational dependence rather than only random seeds:
unary selection, relation-conditioned effects, two-hop composition, and permutation-invariant
aggregation. Target programs must be deduplicated behaviorally, and every episode must pass an
oracle identifiability and executor audit.

## Matched systems

Development should compare four systems under explicit information accounting:

1. an oracle-grounding relational executor, establishing the DSL and query ceiling;
2. a hard modular system with frozen language grounding and exact relational program search;
3. a probabilistic modular system that preserves alternative entity/relation groundings; and
4. a joint relational neural challenger trained only on development generator families.

The joint challenger needs both a raw-language condition and a privileged parsed-graph condition.
This separates representation failure from dynamics failure and makes the modular system's
structural supervision visible rather than treating it as free. Parameter count, training examples,
intervention traces, and inference compute should be reported, not necessarily forced to be equal.

## Metrics and decomposition

Mechanics remain the inferential unit. Report complete-mechanic exact match, mechanic-macro query
exact match, worst family, target-program retention, empty hypothesis rate, entity/relation grounding
accuracy, permutation consistency, and performance by entity count. Preserve oracle-grounding,
frozen-grounding, oracle-query, and frozen-query decompositions so that binding, induction, and
execution failures remain distinguishable.

## Development-to-final gate

Do not construct a V22 final suite until:

- oracle grounding is exact for every generator family;
- the development generator has no target or graph-identity leakage;
- held-out program, topology, and entity-count splits are structurally disjoint;
- both modular systems and the matched challenger have frozen implementations;
- architecture and hyperparameter choices use development families only; and
- the final generator, strata, seeds, metrics, thresholds, and retry policy are preregistered.

If the modular system fails with oracle language grounding, revise the relational DSL or search
procedure. If only frozen grounding fails, work on entity/relation binding without changing the
dynamics learner. If the privileged joint challenger dominates on held-out entity counts and graph
topologies, demote exact induction toward a verifier or planner. Sequential state mutation should
begin only after this relational source of failure is understood.

## Immediate executable work

Implement the V22 development generator, relational oracle executor, structural/leakage audits,
and symbolic oracle baselines first. No final V22 data, new model extraction, head fitting, or weight
adaptation is authorized by this direction document.
