# Research roadmap after V166

## Frozen branch state

Track A's current external open-set language protocol is closed at V164. The one authorized local residual model
fixed response validity but failed novelty, calibration, and regret gates; protected MASSIVE transfer remains
sealed.

Track C's model-free representation audit is complete. V165 created the finite 3×3 expressibility/evidence
population, and V166's parser-plus-exact version-space method reconstructed every one of the 144 development
contracts. All 48 ambiguous records correctly retained 64 candidates, false primitive creation and false
resolution were zero, and the prospective model-eligible residual was empty.

## Active sequence

1. Preregister an exact evidence-gathering problem over the frozen ambiguous version spaces. Candidate priors,
   query outcomes, interaction costs, terminal loss, horizon, baselines, and noncompensatory gates must be fixed
   before policy scoring.
2. Compare exact Bayes-adaptive query selection with no-query/MAP, random, class-information-gain, and optimal
   open-loop controls. Require positive value of information and history-dependent action selection; if actions
   are equivalent or dominant, freeze the boundary result rather than tuning it.
3. Keep every candidate and decision shadow-only. Interventions may update only a simulated version space; they
   cannot register a primitive, modify trusted state, call a service, or execute.
4. Separately preregister Track B's reversible fixed-ontology sandbox using only trusted concepts. It must test
   typed proposals, preview/commit parity, invariants, independent verification, stale or malformed inputs, and
   complete rollback.
5. Do not integrate provisional concepts into the sandbox. That requires future fresh confirmation and an
   independent approval boundary.

## Model policy

An LLM is not eligible for V166's zero residual. A future model condition requires a separately and prospectively
defined representational residual that deterministic parsing, retrieval, and exact validation cannot solve. It
remains a non-authoritative candidate proposer; API access is optional, never a system dependency.

## Evidence boundary

V165–V166 and the immediate planner successor use project-authored finite-DSL development evidence. They do not
establish unrestricted natural-language understanding, absolute ontology novelty, external transfer, deployment
safety, registration authority, or real execution.
